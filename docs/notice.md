# Responsibilities and limits

ModelPrepper preserves files obtained through authorized access on media you control. Its position is in [intent.md](../intent.md).

## Upstream rights

The project's MIT license covers its own code and docs. Models and other preserved artifacts retain their publishers' licenses.

The default allowlist is MIT and Apache-2.0 with captured evidence at the selected revision. Mixed, missing, unknown, or conflicting evidence needs review. A card tag is not enough.

Possession, redistribution, modification, and use can have different conditions. Exporting files does not automatically establish redistribution rights for every dependency. Keep applicable licenses and notices.

## Applicable law and access

The documents state a project philosophy, not legal advice or a promise about your jurisdiction. Laws, export controls, sanctions, and other applicable restrictions remain your responsibility.

The utility does not bypass publisher gates or obtain unoffered private files. Future gated/private support uses access the user already has and remains opt-in.

A stored revision does not erase an order that applies to you. Archiving does not expand upstream rights.

## Preservation and execution

The utility copies published artifacts. It does not remove safety training or execute arbitrary repository code during preservation.

Default file policies exclude executable repository files and pickle. If a future explicit profile includes code as archival data, that does not authorize executing it.

A checksum proves consistency with recorded bytes or source metadata. It does not prove harmlessness, quality, authentic authorship beyond the recorded trust basis, or successful offline loading.

## User control

Users choose what to preserve and which lawful priorities matter to them. Worry matches affect discovery ranking. They do not alter license evidence, access requirements, file identity, or capacity bounds.

Credentials stay out of manifests, shared collections, and logs. Shared exports carry data and provenance, not the originating user's permission to mutate a vault.
