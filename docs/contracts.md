# Version-one contracts

This document distinguishes implemented contracts from future preservation operations. Unknown fields and unsupported schema versions are rejected. Fixture changes that alter canonical identity require explicit review.

## Implemented configuration

The executable accepts the subset in [examples/config.toml](../examples/config.toml). Required top-level fields are schema_version, catalog_path, licenses, storage, transfer, approval, files, and volumes. watches defaults to an empty list.

Nested structures reject unknown fields. Budgets must be positive. Parallel file count is bounded to 1 through 8. Volume labels and configured paths must be unique, and the default volume must exist.

Only manual approval, UTC weeks, MIT/Apache-2.0, public Hugging Face model sources, propose updates, `publisher-safetensors-v1`, and `selected-gguf-v1` are implemented. The default profile remains `publisher-safetensors-v1`. Discovery, automatic rules, repository code, and extended licenses remain unsupported. `include_repo_code` and `include_gguf` stay rejected. A GGUF preview names each file with `--select` under `selected-gguf-v1`. Do not add the future discovery/worries sections to a config passed to the current validator.

Offline previews record catalog and volume paths as provided. Vault commands resolve relative paths against the canonical configuration file's directory. Overlap is compared after that resolution. ASCII case and a Windows verbatim prefix do not make one directory into two, including when a configured path does not exist yet. Init creates bundled SQLite and volume identities; status measures free space only for a matching mounted volume. Neither command mounts disks.

## Implemented inventory

[tests/fixtures/inventory.json](../tests/fixtures/inventory.json) is synthetic, not captured publisher evidence.

Inventories record source endpoint, repository id/type, requested and resolved revisions, complete-list status, access flags, layout, license evidence, and file records.

The initial resolved commit is exactly 40 lowercase hexadecimal characters. Upstream file hashes distinguish raw SHA-256 from Git blob SHA-1. Xet hashes are not silently reinterpreted as either algorithm.

Each file has path, size, role, required flag, and optional upstream identity. Files must have unique portable paths, including case-insensitive collision and file-as-directory checks. Initial paths are ASCII and at most 240 bytes; Unicode and wider path support require a later explicit policy.

The current planner trusts no input file. Claimed complete layout or matched license status is a preview assertion, not validated publisher provenance. Every local preview carries local_inventory_untrusted and transfer_authorized=false.

## Selection and blockers

Select files using explicit roles and supported extensions. Unsafe tensor formats and repository code are excluded regardless of claimed role. Excluding a required file creates required_file_excluded.

The offline planner checks asserted weight, configuration, tokenizer, and license roles. It does not validate locally asserted layout claims. The online resolver separately checks config.json, tokenizer_config.json when present, and exact closure of a safetensors shard index. Remote-code mappings or explicit trust_remote_code requirements make the layout unsupported. None of these checks proves that a runtime can load the model.

Blockers are stable snake_case identifiers:

| Code | Meaning |
| --- | --- |
| local_inventory_untrusted | Local metadata cannot authorize a source transfer. |
| incomplete_inventory | Full upstream listing was not asserted. |
| unsupported_layout | Inventory uses a layout outside the initial profile. |
| access_restricted | Gated or private source is outside current policy. |
| license_needs_review | Evidence is unreviewed, conflicting, notice_present, or absent. |
| license_not_allowed | Claimed license is outside the configured allowlist. |
| missing_required_role | A required model component category is absent. |
| required_file_excluded | File policy excludes a component asserted required. |
| missing_upstream_hash | Selected file lacks upstream content identity. |
| revision_too_large | Payload exceeds the configured total storage ceiling. |
| transfer_budget_exceeded | Payload exceeds the standalone period transfer allowance. |
| insufficient_space | Payload plus minimum reserve exceeds the supplied free-space observation. |
| ambiguous_gguf_selection | A multi-file GGUF inventory has no named selection. Candidates and sizes are reported. |
| missing_gguf_selection | `selected-gguf-v1` was given no file name, including when the inventory has one GGUF. |
| unknown_gguf_selection | A named path is not a root weight or projector GGUF in the inventory. |
| incomplete_gguf_set | A split named `-NNNNN-of-MMMMM.gguf` is missing a shard. That set is left out of the payload. |

Byte arithmetic is checked for overflow. The current budget checks are standalone lower bounds. They do not account for existing archive occupancy, reservations, transfer history, or workspace. The single-file staging experiment caps its checkpoint database and rollback journal at 1 MiB each. A plaintext loopback fixture measured that request and response bytes for one refreshed segment exceed the allowance charged for that payload. That charge is not a bandwidth ceiling. The recorded connection figures are separate: 128 KiB ureq input, 128 KiB ureq output, 16 KiB rustls received plaintext, 64 KiB rustls outgoing buffer, and a 64 KiB application read. Kernel receive and send buffers are measured on a connected loopback socket and are not copied into the plan. `workspace_bytes` stays null until a bound also covers every selected file. A full GET of a file over 50 GB (50,000,000,000 bytes) is outside this path; payload transfer sends `Range` and does not send `Accept-Encoding`.

## Canonical preview identity

Policy identity is SHA-256 of compact JSON serialized from the version-one Config structure in declaration order. Sort licenses, volumes by label, and normalized watches by repository id/revision first.

Preview identity hashes a compact JSON object whose declaration order is domain, policy_digest, source, inventory. The domain is modelprepper.offline-plan.v1. Normalize official repository URLs to ids, sort inventory files by path, and sort license evidence paths.

Source identity and the complete file inventory, including exclusions and license assertions, are bound to the preview. File size, hash, required flag, evidence, configured placement, or policy changes alter identity. Current free-space observations are not identity. When `selected-gguf-v1` resolves a non-empty file set, identity also binds those sorted paths, so naming one shard of a complete set matches naming every shard. A named request that resolves no files binds the sorted request. An empty selection omits the field. An absent inventory `base` is omitted. The publisher-safetensors fixture id below stays in place.

This format is a project-specific canonical encoding, not a claim of compliance with a separate JSON canonicalization standard. It is frozen by the regression vector below and tests of order invariance.

For the committed config and inventory fixtures:

```text
policy_digest:
3a30ff35811c93095815ea8a4a21fcda725b5c0f9201bf2d33d968d2145a60dc

plan_id:
1cf5f58c1b7819a7f5104edbdf7de51168ca25ca37797e8e48e1f4a9a14d2795

payload_bytes:
5504
```

The future trusted transfer plan gets a distinct identity domain. An offline preview is never upgraded into an authorized plan by editing its output JSON.

## CLI output and errors

A terminal prints plain text: the verdict first, then the facts, then one `next:` step. Identifiers in text are eight characters; JSON keeps the full value. Sizes in text show decimal and binary units. A pipe or `--json` prints one compact JSON object. `--pretty`, and a terminal when JSON was requested, indent that object. `--json` wins over `local list --format text`. Omit `--format` and `local list` follows the terminal. Color applies only to the verdict word and to `next:` commands, using the 16-color ANSI set, and only for text. `--color auto|always|never`, `NO_COLOR`, and `TERM=dumb` control it. JSON is never colored.

On a terminal, clap and application failures share one shape: `error:` and `next:`. Otherwise stderr gets schema_version plus error.code and error.message. The JSON message keeps the operating-system error text. Argument errors exit 2. Application errors exit 1. `verify-local` and a mismatched `adopt` exit 1 when `ok` is false.

A closed stdout or stderr (SIGPIPE / broken pipe) ends the process with status 0 and no panic. The Rust runtime already ignores SIGPIPE; write errors of kind broken pipe are not application failures.

`verify-local` reports schema_version 1 with additive `selected` and `excluded` path lists. `ok` is false when a required file is missing, the wrong size, or the wrong hash, and when an optional file is present but damaged. An optional file that is absent is an exclusion: it is not a failure, it is not copied, and it is not written into the custody manifest. Present matching files, including optional ones, are the only set `adopt` copies, re-hashes, records, retries, and removes on `--move`. The same check runs again after staging; a changed set is `selection_changed` and the staging directory is removed. `adopt` records provenance `upstream-verified (local source)`. Success adds file_count, size_bytes, license_id, and excluded to the JSON object and prints a text receipt whose first word is `preserved`. Failure and partial work do not print that receipt. A partial staging directory is removed when verification fails and is resumed when the process is interrupted before publication. A local-baseline import, which would record bytes without upstream proof, is not implemented. Adoption cannot proceed when the saved review's license evidence is not matched.

Hashing and copying progress goes to stderr. A terminal rewrites one line at most four times a second and then prints `ok` with the file name and size. If that line is still open when the command fails, it is closed before the error text. A pipe prints at most eleven lines per file and does not use carriage returns. `--quiet` prints no progress. The result on stdout is unchanged.

`readiness` reads a schema_version 1 recipe and one local directory. It reports `mode` `offline-preflight`. Integrity, per-capability closure, rights, availability, environment, runtime retention, and `offline_readiness` stay separate. `transfer_authorized`, `network_contact`, `executed`, and `vault_mutated` are false. `provenance` is `declared_only`. The profile `publisher-safetensors-text-v1` requires declared config, tokenizer, weight, and template files for `text-generation`. A retained file at most 2 MiB is hashed. A larger retained file is unverified. Runtime retention is `retained` only when that artifact's bytes match. A larger retained runtime is `unverified`, a present runtime that fails its size or hash check is `damaged`, and an absent retained runtime is `missing`. A named package or a remote URL stays `named` or `remote` and does not satisfy retention. `offline_readiness` is `untested` unless the recipe already contains a drill record that still matches this digest, runtime version, OS, architecture, disabled network, and empty cache, and the selected capability's retained bytes still match. Otherwise a recorded pass is `stale`. The command does not create the directory, follow a link, contact a publisher, execute code, or write a vault. Unknown recipe fields and schema versions are rejected.

`local list` escapes control characters, bidi controls, and backslashes in human-readable fields before constructing rows. JSON preserves the original field values.

`local list` uses schema_version 2. Without `--config`, coverage is `not_checked`, `preserved` is null, and missing roles are empty. With `--config`, coverage is `none_recorded`, `partially_recorded`, or `all_components_recorded`. Counts are distinct usable digests. Unknown media types are kept and can count as `other`. An empty media type, an unknown role, or a digest that is not 64 hex characters makes that component unusable and blocks `all_components_recorded`. `preserved` is true only when every usable component's digest was already in the catalog. That is historical byte identity. It is not a new hash, a mounted-disk check, or proof the model runs offline. A missing volume does not delete those catalog digests. Manifest discovery skips symlinks and Windows reparse points, including a manifests directory that is itself a link, instead of listing the directories they point at.

Adoption requires a real source directory outside the catalog and every configured vault volume, including on retries with an existing preserved copy. A missing volume path still reserves that directory, and a Windows verbatim prefix is the same path. Local license evidence must be a regular file with the captured byte length before it is opened; its hash is streamed in bounded chunks. Symlinks and Windows reparse points within reviewed file paths are rejected. A directory listing records a link and does not descend into it. The same rejection applies when the path given to `verify-local` is itself a link. A link at `preserved` or the adoption staging directory is rejected before a copy or rename can leave the volume. A published directory that already has a custody row must still match that recorded manifest; a missing optional file is not a new exclusion. A regular file in the staging directory that is outside the frozen set, including a leftover partial, is removed before publication. A link there is left in place and rejects the publication.

Before `--move` removes any remaining source files, it checks all of them against their upstream identities and preserved copies, then repeats each check before removing that file. Changed or unsafe files fail cleanup without deleting earlier files during preflight. Files already absent after partial cleanup are allowed on retry; unrelated extra files are retained, and the source directory must still exist. These checks do not provide handle-relative protection against hostile concurrent directory replacement or an atomic multi-file deletion transaction.

Clap argument errors exit 2. Help and version are ordinary text. Successful offline preview, budget, and kit reports exit 0 even when blockers are present: they completed a report rather than a transfer.

Local metadata reads are capped at 2 MiB and require UTF-8, with optional leading BOM. Parser errors avoid echoing a full TOML source excerpt. `resolve`, `propose`, and `verify-local --repo` make publisher requests. `verify-local --config --plan` reads the saved review and does not contact a publisher. Proposal listing, inspection, and rejection remain offline.

config init creates only a config file using exclusive creation. It does not initialize a vault and never overwrites an existing output. Overlapping catalog and volume paths are rejected at generation and at config check with overlapping_vault_paths, before init. A `.` or `..` path segment is rejected there with unsafe_vault_path. Failure during writing is reported; if storage failure leaves a partial config, the user inspects it before retrying.

## Implemented source resolution

resolve accepts a repository id or official hub URL and a bounded revision. It reads the moving revision, then reads its exact 40-character commit. Repository identity, pin, access flags, file paths, sizes, and upstream identities are checked before evidence is fetched. Only public, ungated model repositories are supported.

The complete pinned inventory remains in the output, including excluded alternatives. Root publisher safetensors, conventional configuration/tokenizer files, templates, README, licenses, and notices receive explicit roles. A root `.gguf` whose name contains `mmproj` is a projector. Other root `.gguf` files are weights. Nested paths stay `other`. A repository whose weights are GGUF files and not safetensors is labeled `gguf-v1` instead of `unsupported`, so it can be reviewed. That label does not select GGUF into the safetensors profile, and `include_gguf` stays rejected. `resolve` copies `cardData.base_model`, a string or the first array element, into `inventory.base.repo_id` when it is an official repository id. The base revision and license stay unset, and resolve does not fetch the base. Nested weight variants, adapters, repository code, and pickle weights are not selected by the safetensors profile.

## Selected GGUF preview

`selected-gguf-v1` is opt-in. The preview still carries `local_inventory_untrusted`, and `transfer_authorized` stays false. The operator names each file with repeatable `--select`. The profile does not choose a file on its own. A multi-file inventory with no names is `ambiguous_gguf_selection`. One unnamed file is `missing_gguf_selection`.

A filename matching `-NNNNN-of-MMMMM.gguf` is a split. Selecting any shard of a complete set puts every shard in the plan. An incomplete set is excluded and blocked with `incomplete_gguf_set`. A projector is required only when it is selected. A selection with no weight is `missing_required_role`. A successful selection also carries root license and notice files, including a root `NOTICE` whose role is `other`. Their sizes count in `payload_bytes`. `--select LICENSE` stays `unknown_gguf_selection`. README and unselected projectors stay excluded. This profile does not raise `required_file_excluded` for the files it leaves out. A repository with no license file still uses the inherited-base path below.

The quantization label is the rightmost filename token of each selected GGUF. A longer token that ends at the same place wins, so `UD-Q4_K_M` stays intact. Unmatched GGUF names are `unlabeled`. Labels are joined in path order. License and notice paths do not add a label. The plan records representation `derivative`, the declared base repository or `not declared`, the base revision or `not established`, and the note that a quantization cannot restore the original weights' precision. The label comes from the filename. The plan does not read a GGUF header or execute a file.

A GGUF repository with no matching license file stays unreviewed on its own evidence. The preview may use a base license only when `base.revision` is a 40-character pin and `base.license_status` is `matched` with an id and paths. `license_evidence_source` is then `inherited`, and `license_id` is that base id. A disallowed inherited id is `license_not_allowed` without also adding `license_needs_review`. Otherwise the source is `absent` and the blocker is `license_needs_review`. The inventory status is unchanged. Adoption still requires `matched` evidence, so an inherited preview cannot be adopted on that status.

This named derivative bundle is the explicit exception to the whole-repository rule in [video-review.md](video-review.md). The default profile still previews the safetensors set.

## Offline budget

`budget` reads schema 1 JSON. Each candidate has `name`, and may have `inventory`, `select`, `representation` (`original` or `derivative`), and `size_known`. An unknown `schema_version` returns `supported: false`, blocker `unsupported_schema`, and `rewritten: false`. The request file is left unchanged.

A row reports pinned required bytes, remaining bytes against `max_stored_bytes` as if that row were stored alone, the shortfall, and blockers. `workspace_bytes` is null. `size_known: false`, a missing inventory, or an ambiguous, missing, incomplete, or unknown GGUF selection is `unknown_size` and is not added as zero. An unsupported layout keeps the pinned required-file sizes and blocker `unsupported_layout`. A required size equal to the ceiling is at-ceiling with shortfall 0. A larger size is `revision_too_large`. The combined total counts each `repo@revision:representation:select-key` once. `select-key` is empty unless the representation is `derivative`. When a row size is unknown and the known sum is within the ceiling, combined remaining is null. When the known sum already exceeds the ceiling, the shortfall is a lower bound. `transfer_authorized` stays false. The comparison does not reserve space.

## Collection preview

`collection preview` reads schema 1 TOML, as in [examples/collection.toml](../examples/collection.toml). Required fields are `name` and `entries`. `name` is 1 to 80 characters. `replica`, when present, is a volume label of at most 64 letters, digits, `-`, or `_`. It is recorded and no copy is made. `ceilings`, when present, is an array of `category` and `bytes`. `category` is a kit slot name: `text`, `coding`, `vision`, `image_generation`, `video_generation`, `speech_to_text`, `text_to_speech`, `embeddings`, or `reference`. `bytes` is an integer of zero or greater. At most one ceiling is accepted for each category. The preview records that number and does not charge an entry against it or reserve those bytes. `applied` stays false. An absent `ceilings` key is an empty list. Each entry has `repo_id` and `revision`, and may have `note` of at most 200 characters, `representation`, `categories`, `base_repo`, `base_revision`, `evaluation_source`, `evaluation_name`, `evaluation_value`, `evidence`, and `provenance`. `provenance` is 1 to 200 characters without control characters. It is the operator's conversion or training statement. `provenance_verified` stays false. An absent statement is null, and the text says `provenance not stated`. The preview does not check it. `evidence` is `present` or `missing`. It is the operator's statement, not a file check. `evidence_checked` stays false. An absent statement is null, and the text says `evidence not stated`. An evaluation is recorded only when all three text fields are present. Each is 1 to 80 characters without control characters. The text is not parsed as a score. `ranked` stays false. An absent evaluation is null, and the text says `evaluation not attributed`. The preview does not order entries by it. `categories` is an array of kit slot names. An entry may name more than one slot. A repeated name in one entry is refused. At most one of each slot is accepted. An absent or empty array stays empty, and the text says `uncategorized`. Naming a slot does not charge a ceiling. `representation` is `original-required`, `original-preferred`, or `selected-derivative`. When it is absent the report uses null and the text says `unspecified`. The preview records that name and does not defer, substitute, or reserve bytes for it. `base_repo` is normalized like `repo_id`. `base_revision` is checked as text and is not resolved. A revision without a repository is refused. An entry cannot name its own repository and revision as its base. When `base_repo` is absent, both JSON fields are null and the text says `base not declared`. When the revision is absent, the text says the revision is not established. `base_preserved` stays false. The preview does not fetch the base or treat the entry as proof that the base is preserved. When two or more entries name the same `base_repo` and established `base_revision`, the report lists that base once with the entry count. `deduplicated` stays false. A base whose revision is absent is not grouped. The preview does not drop either entry or claim a byte saving. A hub URL is normalized to `owner/model`. The revision is checked as a branch, tag, or commit reference and is not resolved. At most 100 entries are accepted. The same `repo_id` and `revision` cannot be repeated. Unknown fields are refused. A missing or non-1 `schema_version` returns `supported: false` and does not parse entries. The file is not rewritten.

`transfer_authorized`, `network_contact`, `vault_mutated`, and `downloads_started` are false. `workspace_bytes` is null. `resolved` is false on every entry. This preview does not apply a representation policy, charge a category ceiling, prove that a declared base is preserved, drop a repeated base, rank entries, or discover repositories. An entry may name kit slots, and those names may overlap. The preview records them and does not charge a ceiling. An evaluation attribution is recorded and not ranked. An evidence statement is recorded and not checked. A provenance statement is recorded and not verified. A repeated entry identity is refused. A repeated declared base is listed and not merged. `replaced` stays false.

`collection store --config <file> --file <file>` parses that same schema 1 file. An unknown schema returns `supported: false` with action `store`, does not open the catalog, and does not write. A supported file requires an initialized vault. Catalog schema 7 adds `collections`, `collection_ceilings`, `collection_entries`, and `collection_entry_categories`. Opening a catalog at schema 1 through 6 creates those tables. The command replaces only the rows for that collection name. Custody, volumes, proposals, grants, replicas, and period charges stay in place. A failed write leaves the previous list in place. Replacing a stored name does not delete archived revisions. `vault_mutated` is true after the commit. `replaced` is true only when that name was already stored. `transfer_authorized`, `network_contact`, and `downloads_started` stay false. `workspace_bytes` stays null. `resolved`, `applied`, `ranked`, `evidence_checked`, `provenance_verified`, `base_preserved`, and `deduplicated` stay false.

`collection show --config <file> --name <name>` reads that stored list. A missing name is `collection_not_stored` and does not write. `vault_mutated` and `replaced` stay false. The same application flags stay false.

`collection list --config <file>` pages those stored names in name order. `--limit` is 1 to 100 and defaults to 20. `--after` returns names that sort after that cursor, which is the last name on the previous page. An empty catalog is a successful empty page. `ranked` stays false. The page does not order by evaluation text, entry count, or replica, and it does not write. `vault_mutated` stays false. `transfer_authorized`, `network_contact`, and `downloads_started` stay false. `workspace_bytes` stays null.

`collection remove --config <file> --name <name>` deletes that stored name. The returned report is the list that was deleted. Ceilings, entries, and category names for that name go with it. Custody, volumes, proposals, grants, replicas, and period charges stay. Archived revisions stay. A missing name is `collection_not_stored` and does not write. An empty, control, or too-long name is `invalid_collection` before the catalog opens. `vault_mutated` is true only after the delete commits. `replaced` stays false. `transfer_authorized`, `network_contact`, and `downloads_started` stay false. `workspace_bytes` stays null. The same application flags stay false.

`collection custody --config <file> --name <name>` counts custody rows whose `repo_id` and `resolved_revision` equal a stored entry's repository and revision text. The count is rows, not plans merged together. Distinct provenance strings on those rows are reported in plan id order and are not checked again. A branch, tag, or different commit does not match. A replica row is not a custody row. An empty stored list is a successful report with no entries. A missing name is `collection_not_stored` and does not write. An empty, control, or too-long name is `invalid_collection` before the catalog opens. `resolved`, `provenance_verified`, `evidence_checked`, and `ranked` stay false. `vault_mutated` stays false. `transfer_authorized`, `network_contact`, and `downloads_started` stay false. `workspace_bytes` stays null. The command does not hash files or download. A revision of 40 lowercase hex characters is labeled `commit`. Any other accepted revision is labeled `name`. `main` is `name`. The label is not a resolution, and `resolved` stays false. When every matching manifest records `size_bytes` and those totals agree, `measured_bytes` is that sum. A missing manifest or disagreeing totals leave `measured_bytes` null. A written category ceiling is charged only when every entry that names it has `measured_bytes`. `charged_bytes` is that sum, and the same sum can count toward each category the entry names. `applied` is true only then. `within_written_cap` is true only when that sum is at most the written cap. An unmeasured entry is left out, a category with no named entry is not charged, a partial sum is not reported, and an overflowing sum is not charged. No size is invented. The comparison does not reserve bytes or approve a transfer. Preview, store, and show still leave their `applied` flag false.

`collection export --config <file> --name <name> --output <file>` writes that stored list to a new schema 1 TOML file. The file contains `schema_version`, `name`, an optional `replica`, ceilings, and entries. Absent optional fields are omitted. Flags, shared bases, and approval fields are not written. Previewing the file recomputes shared bases. Comments from the original file are not preserved. The catalog is not changed. `vault_mutated` stays false. An existing output path is left unchanged with `output_exists`. A path with no file name, or a directory that cannot be written, is `export_failed`, and no output file is left behind. A missing name is `collection_not_stored` and creates no file. An empty, control, or too-long name is `invalid_collection` before the catalog opens. An uninitialized catalog is not created. `resolved`, `ranked`, `evidence_checked`, and `provenance_verified` stay false. `transfer_authorized`, `network_contact`, and `downloads_started` stay false. `workspace_bytes` stays null.

`collection diff --config <file> --file <file>` compares one schema 1 file with the stored list of the same name. The comparison uses the parsed replica, ceilings, entries, and the shared bases that preview recomputes. An unknown schema is reported, `matches` stays false, and the catalog is not opened. A missing name is `collection_not_stored` and does not write. An invalid file is `invalid_collection` before the catalog opens. An uninitialized catalog is not created. The file is left unchanged. `vault_mutated` stays false. `resolved`, `ranked`, `evidence_checked`, and `provenance_verified` stay false. `transfer_authorized`, `network_contact`, and `downloads_started` stay false. `workspace_bytes` stays null. `discover --file <file>` searches the reviewed source catalog. Schema 1 names at least one of `role`, `status`, or `id`, and present constraints are combined. Matches stay in catalog order. `--limit` is 1 to 100. `--after` continues after that source id. An unknown schema is reported and not searched. An unknown role, status, or source id is `invalid_discovery`. `ranked`, `transfer_authorized`, `network_contact`, `vault_mutated`, and `downloads_started` stay false. `workspace_bytes` stays null. ## Kit report

`kit` reads schema 1 TOML, as in [examples/kit.toml](../examples/kit.toml). Slots, in order, are `text`, `coding`, `vision`, `image_generation`, `video_generation`, `speech_to_text`, `text_to_speech`, `embeddings`, and `reference`. Each slot is an array of picks: `repo_id`, `revision` (40 lowercase hex or `unpinned`), `representation` (`original` or `selected-derivative`), optional `note`, optional `select`, and optional `evidence` path relative to the kit file. The tool does not fill a slot. An absent known slot is reported empty. An unknown top-level key is an extra slot with reason `unsupported_slot`. Unknown pick fields stay visible as `invalid_pick`. An unknown schema version, or a non-string `hardware_tier`, is `supported: false` with `unsupported_schema`. The file is not rewritten.

Evidence is schema 1 JSON. It may carry `verified_local`, an inventory, or a summary with `source_kind`, `layout`, `license_id`, `gated`, `private`, and `required_bytes`. `verified_local` is that flag. The command does not hash a disk or open a vault. A missing file is `no_saved_review`. A non-Hugging Face summary is `unsupported_source`. Diffusers, video, and audio layouts are `unsupported_layout` and stay visible. A gated or private inventory is `access_restricted`. A license outside the allowlist is `license_not_allowed`. An unpinned revision adds `unpinned` and can still show bytes when the evidence has them. Slot attributed bytes may count one model in several categories. The physical total counts `repo|revision|representation|select-key` once, and `select-key` is present only for `selected-derivative`. `hardware_tier` is echoed and is not a recommendation. `network_contact`, `vault_mutated`, `rewritten`, and `transfer_authorized` are false. `workspace_bytes` stays null.

Repository metadata HTTP 401 is `repository_not_found_or_private`. HTTP 404 on that metadata request is `revision_not_found`. Other file-fetch statuses stay `source_status`.

License and notice bytes are fetched at the pinned commit and verified against their Git blob or LFS identity. Exact text and local SHA-256 remain in the result. Git blob SHA-1 includes the object header; it is never raw file SHA-1.

Matching currently accepts whitespace-normalized Apache-2.0 template text with an optional single filled copyright line in its appendix, or the unchanged MIT permission/warranty text with a narrow heading and copyright prefix. Unknown text, added terms, missing evidence, or mismatched tags remain unreviewed or conflicting. A NOTICE file beside license text that matches is `notice_present`: the notice bytes and hash stay in the evidence, the notice prose is not interpreted, and the status is neither a match nor a conflict. A NOTICE beside license text that does not match stays `conflicting`. Adoption still requires `matched`. Legitimate variants can therefore require later human review. This is intentionally narrower than a general license classifier. Embedded templates in resources/licenses originate from the [SPDX license data](https://github.com/spdx/license-list-data/tree/main/text).

Metadata responses and individual configuration/index files are limited to 2 MiB. License/notice evidence is limited to 16 files and 2 MiB combined. Requests use identity encoding, a 60-second per-request timeout, and at most five redirects. Redirects require HTTPS on huggingface.co or hf.co and their subdomains, without credentials, nonstandard ports, or fragments. A redirected location that returns 401 or 403 is not requested again, including when the refreshed request redirects to that same location. The original URL is requested once more, still without credentials, and a second rejection stops. A 401 or 403 is classified before content encoding, so an encoded error page remains a rejection. A body that may be stored must use identity content encoding; that name matches in any letter case. The signed query is not stored. This refresh does not change a pinned transfer identity. Payload rejection uses `payload_location_rejected` and does not include the address. Transport errors omit URLs and response bodies to avoid exposing signed locations. Rust TLS uses bundled Mozilla roots; custom OS certificate authorities are not supported yet.

Resolution returns mode=resolved_inventory and transfer_authorized=false. Output JSON is an inspection result, not a persisted approval or trusted transfer plan. Feeding its inventory into the local preview retains local_inventory_untrusted.

## Implemented vault foundation

init --config creates a catalog directory, catalog.sqlite3, writer.lock, and a .modelprepper-volume.json identity on each configured empty volume. Catalog schema 2 records vault ownership, initialization, volume UUIDs/labels/absolute paths, and durable source reviews. Schema 1 upgrades transactionally without changing identities. SQLite uses WAL, synchronous=FULL, and foreign keys. The catalog must be local. Windows UNC catalog paths are rejected before the volume probe. A classified network filesystem, including a mapped drive whose type is remote, cannot hold the catalog or a checkpoint journal. It can hold payload. FAT, exFAT, an unknown type, and a read-only mount are refused before a catalog, checkpoint, or payload write. ext4, APFS, and NTFS are the baseline. btrfs, xfs, tmpfs, and zfs are accepted local filesystems and are not that baseline. `status` reports the mounted kind, its role, and whether the mount is read-only. An offline path stays `unmeasured`.

Catalog and volumes cannot overlap. Dot segments, symlink ancestors, reparse points, and unrelated files during adoption are rejected. Ownership checks also cover SQLite sidecars. A kernel-held exclusive file lock covers the database operation; a contending writer receives writer_busy. These checks assume other programs do not maliciously replace directories during the operation; handle-relative filesystem operations remain a later hardening gate.

Initialization commits disk identities to the catalog before publishing volume markers. A valid pending identity can be renamed and initialization resumed with the same UUIDs. Recovery preflights all configured volumes before writing any markers. Malformed pending identities or an incomplete schema fail closed for inspection. Recovery from every power-loss boundary is not qualified yet.

Once initialization reaches ready, init never recreates a missing volume or adopts a replacement. Existing user payload files are retained. Status reports mounted, offline, identity_missing, or identity_mismatch per volume, plus the filesystem kind when the path exists. Invalid marker text is an application error. The top-level ready state means catalog initialization completed; availability is reported separately for each disk.

status is offline, acquires the writer lock, opens only an existing catalog, and checks identities before measuring free bytes. It can update SQLite journal bookkeeping, so it is not a read-only media command. It also lists preserved copies and, when a healthy replica row exists, that replica's volume. `upstream-verified (local source)` means the bytes matched a resolved commit and its captured license evidence. `local-baseline` means `import` recorded the bytes without upstream proof. A replica line is another volume copy, not a separate failure domain. Changing a configured disk path or label fails with volume_configuration_changed. Relocating a volume requires a future explicit operation.

An optional Omarchy bar widget in [plugins/omarchy-presence](../plugins/omarchy-presence/README.md) projects this status object. It is not part of the CLI, it is not installed with the binary, and it is not a second custody verdict. Its only command is `status`. A refresh passes `--json`. Open inspection uses the same command without `--json` and shows that output as a transcript, not as a new snapshot. A transcript does not clear a failed status or turn text into a malformed snapshot. A timed-out or capped inspection likewise leaves the snapshot and its failure in place. The projection keeps writer-busy, missing config, invalid config, malformed output, timeout, and stale data distinct, and it labels catalog rows as historical provenance. An Omarchy session has not validated the widget.

## Future manifest contract

The [source review contract](source-reviews.md) describes propose, proposals list/show, and decide. Reviews bind original evidence in a distinct identity domain; transfer approval remains unavailable. Rejected reviews are retained. A source review is not the future executable transfer plan or a manifest.

The durable manifest in [preservation.md](preservation.md) contains schema version, bundle identity, source identity, rights, file hashes and sizes, the selected profile, excluded paths, and dependencies. `fetch` writes `modelprepper-bundle.json` inside the sealed folder, including provenance `upstream-verified (ranged https)`. The file has no timestamp, so a repeated seal can match the same bytes.

A trusted seal is created only after the selected bytes have been fully hashed. `import` records `local-baseline` and cannot acquire upstream provenance by matching a known layout. `rebuild` reads published bundles and does not copy grants or approval decisions. Catalog schema 5 adds the replicas table. A replica row exists only after the destination hashes match. Catalog schema 6 adds `period_charges`, one UTC-week payload total per plan. That counter is not `workspace_bytes`. `watch` writes a row only after a fetch newly seals. Catalog schema 7 adds the collection tables. A stored list is not a seal and is not `workspace_bytes`.

## Future job-state contract

Decision states: pending, approved, rejected. Approval binds a trusted immutable plan identity.

Transfer states: queued, reserved, downloading, paused, retry_wait, verifying, publishing, sealed, blocked, damaged, cancelled.

Only approved plans may enter queued. Verification and durable publication precede sealed. Loss of a mounted drive affects availability, not integrity. Repair creates an operation pinned to the archived identity. Resume does not change that identity.

Detailed recovery behavior is in [architecture.md](architecture.md). Persistent jobs and transitions are not implemented in the offline preview.
