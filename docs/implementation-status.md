# Implementation status

This records executable behavior and evidence as of November 3, 2026. It does not mark the preservation roadmap complete.

## Executable features

| Operation | Current behavior | Remaining boundary |
| --- | --- | --- |
| config init/check | Exclusive config creation and strict validation. | No automatic configuration migration. |
| init | Bundled local SQLite, writer lock, stable vault/disk UUIDs, empty-directory adoption. | Full power-loss recovery and filesystem qualification remain open. |
| status | Offline catalog and mounted identity check, actual free bytes, and preserved local copies. | No downloaded bundles, jobs, reservations, replicas, or relocation yet. |
| resolve | Moving ref followed by pinned metadata; verified license/config/index bytes. GGUF-only repos report layout `gguf-v1`. A root `mmproj` GGUF is a projector. `cardData.base_model` is recorded as a repository id. A NOTICE beside matching license text is `notice_present`, not a conflict and not a match. | Public ungated models only; no payload download or approval. Resolve does not fetch the declared base or establish its revision. Notice prose is not interpreted. |
| verify-local / adopt | Read-only hash against a resolved commit, then copy or move the frozen matched set. Absent optional files are exclusions. Provenance is `upstream-verified (local source)`. | Not a download and not a local-baseline import. License evidence must already match. |
| local list | Read-only Ollama manifest inventory. Coverage is unchecked, none, partial, or fully recorded. Symlinks and Windows reparse points are skipped. | A catalog match is historical byte identity, not a fresh hash or an offline run. Does not import blobs or call the Ollama API. |
| propose / proposals / decide | Durable evidence/volume binding, paginated offline inspection, idempotent rejection, schema-1 migration. | Approval is blocked until transfer bounds and accounting qualify. |
| plan | Canonical preview from local inventory. `publisher-safetensors-v1` is the default. `selected-gguf-v1` previews files named with `--select`, keeps a complete split set together, labels a projector, carries root license and notice files, and can inherit an already captured base license. A quantization label is the GGUF filename token. | Always untrusted, never persisted or authorized. `include_gguf` stays rejected. License and notice paths do not add a quantization label. An inherited license does not change the derivative inventory status, and adopt still requires `matched` evidence. |
| budget | Offline table of pinned inventory sizes against `max_stored_bytes` and `min_free_bytes`. Unknown sizes stay unknown. The same artifact is summed once. | Does not reserve bytes, measure workspace, or approve a transfer. `workspace_bytes` stays null. |
| kit | Schema 1 TOML slots filled only by the operator. Status comes from a saved evidence file. Category totals may overlap; the physical total counts a model once. An unknown schema is reported and the file is left unchanged. | Does not fill a slot, recommend a model, contact a publisher, or write a vault. Adapter-less layouts stay visible as unsupported. |
| readiness | Read-only recipe preflight for `publisher-safetensors-text-v1`. Reports capability closure, declared rights, disk presence, and whether a recorded drill still applies. A retained runtime is `unverified` when it is larger than 2 MiB and `damaged` when the present file does not match. | Not a download, not a runtime execution, and not a new drill. A named package or URL is not a retained runtime. An oversized or mismatched runtime is not reported as missing. |
| Integrity library | Bounded-memory Git blob/LFS verification plus local SHA-256. | Transfer writer and durable manifest integration are next. |
| Transfer library experiment | Identity-bound prefix checkpoints, strict byte ranges, segment rollback, full-file upstream verification, offline uncommitted-tail recovery, exclusive SQLite checkpoint sessions. Each segment allowance is charged before the request and kept when a tail is discarded. The checkpoint database and its rollback journal are each capped at 1 MiB. A redirected 401 or 403 is refreshed once from the original URL; the rejected location is not retried or stored, even when the refresh names it again. An encoded 401 or 403 stays a rejection, and identity content encoding matches in any letter case. A plaintext loopback fixture counts the request and response bytes for that attempt. A ranged GET omits `Accept-Encoding`. Recorded buffers are 128 KiB ureq input, 128 KiB ureq output, 16 KiB rustls received plaintext, 64 KiB rustls outgoing, and 64 KiB application read. Kernel socket buffers are measured on a loopback socket. | That cap is not `workspace_bytes`. The plaintext wire count is not the TLS or kernel measurement. `workspace_bytes` stays null. Approval, vault reservations, and publication remain open. |

No command executes repository code. No automatic scan, account service, telemetry, deletion, or conversion exists.

An optional Omarchy presence chip in [plugins/omarchy-presence](../plugins/omarchy-presence/README.md) projects `status` into disk presence, free space, and historical custody rows. It is not installed, not published, and not part of the CLI. `qmllint`, click, Escape, disable, restart, and removal have not been run.

## Observed evidence

- Native Windows unit, CLI, contract, HTTP, integrity, and vault tests pass. Additional [validation drills](validation-drills.md) exercise abrupt process termination, the live NTFS test vault, and durable pinned-source decisions.
- HTTP fixtures exercise bounded reads, interruptions, redirect trust, signed-URL redaction, bad status/encoding, access restrictions, source changes, and metadata disagreement.
- Rights fixtures reject missing, changed, conflicting, and excessive evidence. A matching license beside a NOTICE is `notice_present` and is not adopted. Shard fixtures require exact index closure over selected weights.
- Vault fixtures exercise competing writer ownership, stable IDs, unrelated data rejection, all-volume preflight, interrupted marker publication, missing/substituted disks, schema/configuration drift, Windows junctions, and verbatim path aliases.
- Source-review fixtures cover restart persistence, policy changes, exact decisions, offline disks, corruption, pagination, and identity-preserving migration. Native installer fixtures cover verification, version mismatch, archive path rejection, retained configuration, and upgrades.
- A Windows release builds with bundled SQLite and Rust TLS. Import inspection finds only OS DLLs.
- Offline fixtures for the optional Omarchy presence projection cover mounted, offline, missing, and replaced disks, writer contention, invalid and malformed status, missing executables, hostile paths, timeouts, stale snapshots, a changed config, a capped read that still opens a waiting inspection, and an inspection transcript, timeout, or output cap that does not replace the snapshot or clear a failed status. They check the launched arguments. They do not run `qmllint` or an Omarchy session.
- Live source inspection pins SmolLM2-135M-Instruct at 12fd25f77366fa6b3b4b768ec3050bf629380bac. Configuration bytes verify; missing license text remains unreviewed despite the Apache tag. No weights were fetched.
- A second release inspection pins Qwen2.5-0.5B-Instruct at 7ae557604adf67be50417f59c2c2f167def9a775. License/config/tokenizer configuration bytes verify, and the Apache template with its filled appendix copyright matches. Transfer authorization remains false; no weights were fetched.

Local Windows validation passes 155 Rust tests and 30 documentation-tool tests. Formatting and Clippy with warnings denied pass on Rust 1.99.1. Markdown lint and local links pass. The documentation link library measures 100% line and branch coverage. The CI coverage gate requires at least 80% of owned Rust lines and a real branch measurement; a new local percentage is not claimed until that job measures this tree. CLI captures are regenerated from the release executable. Dependency audit and license checks run in CI against the current lockfile. Offline installer fixtures run from the release binary. A release smoke test creates an empty vault and reports its mounted disk without contacting a publisher. Current artifact sizes are observations, not distribution guarantees.

Live source state can change. These checks are observations, not permanently pinned model recommendations. Use resolve to inspect a current source and retain the exact commit/evidence before later approval.

The single [CI workflow](https://github.com/blisspixel/ModelPrepper/actions/workflows/ci.yml) runs native Linux/macOS/Windows checks, coverage, documentation/capture checks, and dependency audits. Its aggregate Main checks job requires all jobs to succeed. Consult the actual main-branch run for hosted status; local results do not substitute for a hosted run. Native fixture/build results still do not qualify clean-machine, large-volume, power-loss, or offline model-loading behavior.

The [durable staging journal](staging-journal.md) adds exclusive single-file checkpoint sessions and crash-boundary tests. The single CI workflow exercises these tests on Windows, macOS, and Linux. Verify the main-branch run against the exact commit being used; a previous successful run does not validate newer changes.

## Next delivery gates

The order is the work-wave table in the [roadmap](roadmap.md). This list is the same order, with the evidence each gate still needs.

1. Wave 1 is on main. A successful `selected-gguf-v1` selection carries root license and notice files, including a `NOTICE` whose role is `other`. Getting-started runs `examples/budget.json`, `examples/recipe.json`, and `examples/readiness`.
2. Wave 2 is implemented. The single-file experiment rejects ignored Range, changed identity, corrupt partials, truncated bodies, and exhausted segment allowances, and it resumes after process termination. It records the charged allowance and a 2 MiB side-file cap. A redirected payload location that returns 401 or 403 is requested again from the original URL once; that location is not repeated, even when the refresh names it again, and it is not stored or allowed to replace the pinned identity. The segment is charged once. An encoded 401 or 403 stays a rejection. A plaintext loopback fixture measured that the bytes read and written for that refreshed attempt exceed the charged allowance, so the charge is not a bandwidth ceiling. The recorded connection figures are 128 KiB ureq input, 128 KiB ureq output, 16 KiB rustls received plaintext, 64 KiB rustls outgoing buffer, and a 64 KiB application read. Kernel receive and send buffers are measured on a connected loopback socket. A ranged GET sends no `Accept-Encoding`, and a ranged body that is not 206 is not appended. A full GET above 50 GB stays outside this path. Preview `workspace_bytes` stays null.
3. Wave 3 is implemented. One frozen set is staged as one single-file checkpoint session per member, including license and notice. An ignored range is still not appended, and a reopened tail is discarded without refunding the allowance. Part files stay part files. There is no seal and no fetch command.
4. Wave 4. One granted approval bound to that identity, the measured bounds, the volume UUID, and the policy digest. It expires when any of those change. Original evidence, inventory, exclusions, volume UUID, and policy digest are already retained in source reviews. A watch entry still does not fetch.
5. Wave 5, which completes M3. Reservations, full-file verification, durable manifest, atomic publication, and reconciliation after every catalog and filesystem crash point. A renamed directory alone cannot count as sealed. The offline-load drill in issue 29 runs on that sealed test model and not before it.
6. Wave 6, which is M4. Replica copying and manifest reconstruction of that revision with the hub unreachable and the original catalog removed. Unattended watches wait until this passes.
7. Waves 7 through 9. Bounded watches (M5), filesystem qualification (M6), then installation and scheduling (M7). A native Xet client, chunk deduplication, torrents, and a second hub are outside these gates. The transfer spike records why.

Initialized disks and successful inspection are useful foundations. They do not establish that a model has been preserved or can run offline.
